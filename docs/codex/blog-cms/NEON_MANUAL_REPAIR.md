# راهنمای دستی اصلاح دیتابیس Neon

وضعیت: خطای آنلاین `column "primary_language" does not exist` در Vercel تأیید شده است. فایل همراه `NEON_MANUAL_REPAIR.sql` اصلاح مورد انتظار برای دیتابیس قبل از CMS را انجام می‌دهد؛ روی Neon هنوز اجرا نشده است. تست محلی روی دیتابیس جداگانه55432 در چهار سناریو موفق بود. نیازی به نصب افزونه برای اجرای دستی خودتان نیست.

1. در Vercel پروژه دقیق **salsal.team** با آدرس **salsalteam.vercel.app** را باز کنید. از **Storage**، دیتابیس Neon متصل را انتخاب و **Open in Neon Console** را بزنید. اگر این اتصال در Storage نیست، وارد حساب موجود Neon شوید؛ دیتابیس جدید نسازید. شاخه و نام دیتابیس باید همان مقصد DATABASE_URL محیط Production باشند؛ فقط نام main یا production برای تشخیص کافی نیست. اطلاعات اتصال/رمز را در گفتگو نفرستید. اگر مقصد مشخص نیست، پیش از اجرای SQL متوقف شوید.
2. از شاخه اصلی، یک شاخه جدا با نام **before-blog-cms-20261009** و گزینه شامل **schema + data / current state** بسازید. این شاخه پشتیبان باید دست‌نخورده بماند. نام شاخه اصلی، نام دیتابیس و زمان ساخت را ثبت کنید. در SQL Editor شاخه پشتیبان، `SELECT count(*) FROM blog_post;` را اجرا و وجود مقاله‌ها را بررسی کنید. فقط نسخهٔ schema-only کافی نیست. اگر پلن/سهمیه اجازه ساخت شاخه نمی‌دهد، ادامه ندهید؛ خطای سهمیه را اطلاع دهید تا روش پشتیبان دیگر انتخاب شود.
3. یک شاخه دیگر از همان شاخه اصلی با نام **test-blog-cms-20261009** و شامل schema+data بسازید. **SQL Editor** را باز کنید، شاخه تست و همان نام دیتابیس را انتخاب کنید. با نقش مالک دیتابیس اجرا کنید. تمام محتوای فایل **NEON_MANUAL_REPAIR.sql** را یکجا paste و **Run** کنید. این کار DATABASE_URL سایت را تغییر نمی‌دهد. فقط قسمتی از فایل را انتخاب یا اجرا نکنید.
4. نتیجه موفق باید نسخه **002-blog-cms.sql**، ستون‌های **primary_language / editorial** و جدول **blog_image** را نشان دهد. اگر هر خطا یا پیام **STOP** دیدید، ادامه ندهید، دستور `ROLLBACK;` را اجرا کنید و فقط متن خطای بدون اطلاعات اتصال را بفرستید. محافظ‌های فایل را حذف نکنید. فایل، وجود ساختار نیمه‌اعمال‌شده یا تاریخچه ناسازگار را عمداً رد می‌کند و نباید کورکورانه تغییر داده شود.
5. بعد از موفقیت شاخه تست و تأیید وجود داده در شاخه پشتیبان، در SQL Editor به **شاخه اصلی متصل به Production** و همان دیتابیس برگردید. هنگام اجرا کسی مقاله‌ای را ویرایش نکند. همان فایل کامل و بدون تغییر را یکجا اجرا کنید. فایل تغییرات را در تراکنش اعمال می‌کند، نسخه002 را ثبت می‌کند و تعداد/اثر انگشت همه فیلدهای قبلی مقاله‌ها را قبل و بعد مقایسه می‌کند. در صورت خطا تراکنش قابل تأیید نیست و باید rollback شود؛ برای بازیابی بعد از اجرای موفق، شاخه پشتیبان نگه داشته شده است. این فایل رکورد مقاله، کاربر یا نقش را حذف/بازنویسی نمی‌کند؛ قید یکتایی قدیمی slug را طبق مهاجرت اصلی با ایندکس‌های یکتایی زبان جایگزین می‌کند.
6. در صورت موفقیت، https://salsalteam.vercel.app/fa و /en و صفحات مقاله‌های قبلی را تازه کنید؛ برای همین تغییر ساختار دیتابیس، commit/push تازه لازم نیست. ورود و دسترسی مدیر را هم بررسی کنید. اگر هنوز500 بود، متن خطای جدید یا digest را بفرستید؛ موفقیت اجرای SQL به‌تنهایی سلامت همهٔ بخش‌های سایت را ثابت نمی‌کند. شاخه پشتیبان را نگه دارید. داده محلی را به آنلاین import نکنید و db:setup / reset / seed اجرا نکنید.

فایل فقط baseline مورد انتظار001 بدون اشیای CMS002 را قبول می‌کند. اگر002 قبلاً ثبت شده یا بخشی از تغییرات وجود دارد، نیاز به بررسی خروجی schema و اصلاح هدفمند داریم؛ این توقف محافظتی است. تست موفق محلی جای آزمون روی شاخه Neon و بررسی واقعی اطلاعات را نمی‌گیرد.
